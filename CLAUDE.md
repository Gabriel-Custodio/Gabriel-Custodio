# Fábrica de Cortes - Regras do Projeto

## Ambiente e Execução
- **SO:** Windows 10/11 | **Python:** 3.15 (não usar bibliotecas incompatíveis como `faster-whisper`).
- **Dependências:** Sempre chamar `yt-dlp` como módulo (`sys.executable, "-m", "yt_dlp"`) e usar o FFmpeg local em `./bin/ffmpeg.exe`.
- **Python do projeto:** Usar sempre o Python do ambiente virtual (`.venv\Scripts\python.exe`) no `iniciar.bat`.
- **API:** Credenciais ficam no arquivo `.env` na raiz (nunca expor chaves no código).
  - `GROQ_API_KEY`: Chave da API Groq (transcrição Whisper, análise de frames e roteiros por IA). Copie `.env.example` para `.env`.
  - `GROQ_VISION_MODEL` / `GROQ_TEXT_MODEL` (opcionais): trocam os modelos padrão sem editar o código.

## Arquitetura dos Arquivos
- `iniciar.bat`: Menu principal em Batch (manter codificação ASCII sem acentos nos `echo` para não quebrar no CMD). Usa `.venv\Scripts\python.exe` e oferece 4 opções: buscar tendências, gerar cortes com áudio original, gerar cortes com narração IA, gerar cortes modo Gameplay/Streamer (tela dividida).
- `buscar_tendencias.py`: Busca vídeos em alta no YouTube via `yt-dlp`.
- `gerar_cortes.py`: Baixa legendas automáticas do YouTube (`.vtt`/`.json3`), seleciona os melhores trechos via IA e renderiza cortes verticais `1080x1920` na pasta `cortes_prontos/`.
  - **Proteção contra erros 403/JS runtime:** O YouTube exige um runtime JavaScript (Node.js, Deno ou Bun) e o pacote `yt-dlp-ejs` (vem com `yt-dlp[default]` no `requirements.txt`; o `verificar_dependencias.py` instala o Node via `winget install OpenJS.NodeJS.LTS`). Os comandos `yt-dlp` usam `*ytdlp_js_args()` (acrescenta `--js-runtimes node` só se o Node existir; nunca fixar `--js-runtimes node` no código), `--rm-cache-dir --extractor-args "youtube:player_client=android,web"` com fallback automático para `player_client=web` se o primeiro falhar.
  - **Modo `--audio original`**: Mantém áudio original do vídeo, usa legendas do YouTube sincronizadas com o corte.
  - **Modo `--audio ia`**: Gera narração com `edge-tts` (voz `pt-BR-AntonioNeural`), cria roteiro viral resumido com gancho forte, remove áudio original (`-an`), ajusta duração do vídeo ao MP3 gerado (acelera/desacelera vídeo via `setpts`) e sincroniza legendas `.ass` com a narração.
    - **Bug fixes aplicados (2025):**
- **Modo `--audio gameplay` (NOVO)**: Modo Gameplay / Streamer com tela dividida (split-screen).
  - **Quantidade de cortes configurável**: Pergunta interativa no terminal (padrão 5, aceita 1-10).
  - **Seleção de momentos (REGRA: a IA escolhe, o código calcula)**: o título/texto de um corte NUNCA pode vir de algo que a IA escreveu sobre o tempo.
    * `build_gameplay_candidates()` monta candidatos a partir da transcrição REAL em todo o vídeo: início/fim em limites de fala (segmentos), duração `GAMEPLAY_CLIP_DURATION_MIN`-`MAX`, e só entra quem tem fala suficiente (`GAMEPLAY_MIN_CLIP_WORDS`=30 palavras e `GAMEPLAY_MIN_WORDS_PER_SECOND`=0,8).

    * Título da faixa: o `hook_data` que a IA devolveu para o candidato (baseado só no texto real) ou, se faltar, `generate_hook_and_question()` com o texto real. Nome do arquivo: `clip_file_title()` (título do gancho, ou começo da fala real). O `.json` ao lado traz `transcricao` real, `fonte_titulo`, `palavras`, `faixa_do_video`, `score_selecao`.

  - **Seleção de posição da webcam**: Pergunta interativa no terminal (7 opções):
    [1] Canto inferior esquerdo (padrão, x=0.0, y=0.72, w=0.26, h=0.28)
    [2] Canto superior esquerdo (x=0.0, y=0.0, w=0.26, h=0.28)
    [3] Canto inferior direito (x=0.74, y=0.72, w=0.26, h=0.28)
    [4] Canto superior direito (x=0.74, y=0.0, w=0.26, h=0.28)
    [5] Meio-direita / acima do minimapa (x=0.772, y=0.450, w=0.222, h=0.242)
    [6] Detectar automaticamente com IA (Groq Vision: extrai 1 frame, retorna x,y,w,h normalizados 0.0-1.0; fallback para sem webcam se não encontrar)
    [7] Sem webcam (apenas zoom central 9:16 no gameplay)
  - **Enquadramento vertical 1080x1920 via FFmpeg (filter_complex)**:
    * Com webcam (opções 1-6): Dois recortes (crop) empilhados com `vstack`:
      - Topo (webcam): Crop com coordenadas da opção escolhida → `scale=1080:620:force_original_aspect_ratio=increase,crop=1080:620`
        - Para opção [5] (meio-direita): `crop=iw*0.222:ih*0.242:iw*0.772:ih*0.450,scale=1080:620:force_original_aspect_ratio=increase,crop=1080:620`
      - Base (gameplay): Recorte central 9:16 (`crop=ih*9/16:ih:(iw-ih*9/16)/2:0`) → `scale=1080:1300`
      - Junção: `vstack=inputs=2` = exatamente 1080x1920
    * Sem webcam (opção 7): Crop central 9:16 + `scale=1080:1920`
  - **Áudio original**: Mantém faixa do streamer, aplica `loudnorm=I=-16:TP=-1.5:LRA=11` + `fade-out` de 1.5s (vídeo e áudio).
  - **Legendas**: `.ass` na linha divisória (`MarginV=1240`), fonte negrito, borda preta 5px, cor amarela (`&H00FFFF00`).
  - **Prefixo de saída**: `corte_gameplay_` na pasta `cortes_prontos/`.
  - **Detecção automática (opção 6)**: Função `detect_webcam_position_ai()` extrai frame em 10% da duração do vídeo, envia para Groq Vision (`qwen/qwen3.8-27b` por padrão) com prompt estruturado para retornar JSON com coordenadas normalizadas. Validação: coordenadas devem estar em 0.0-1.0 e crop não pode sair dos limites. Se falhar ou não encontrar webcam → fallback para opção 7 (sem webcam).
  - **Funções novas**: `find_best_clips_gameplay_ai()`, `build_gameplay_candidates()`, `select_band_candidates()`, `analyze_band_with_ai()` (recebe candidatos reais), `real_text_for_range()`, `has_enough_speech()`, `clip_file_title()`. Constantes: `GAMEPLAY_TIME_BANDS=6`, `GAMEPLAY_CLIPS_PER_BAND=2`, `GAMEPLAY_MIN_GAP_SECONDS=300`, `GAMEPLAY_DEFAULT_CLIPS=5`, `GAMEPLAY_MIN_CLIPS=1`, `GAMEPLAY_MAX_CLIPS=10`.
      1. **Legenda pulando/duplicada**: Modo IA usa EXCLUSIVAMENTE eventos `WordBoundary` do `edge_tts.Communicate.stream()` — NUNCA usa `.vtt` do YouTube. Estilo `.ass` único (`Alignment=2`, `MarginV=320`), zero sobreposição, sem alternância de estilos (sem karaoke).
      2. **Voz sem respiro**: `generate_viral_script()` garante pontuação natural rigorosa (vírgulas, pontos, exclamações a cada frase curta) e NÃO remove pontuação antes de enviar ao `edge-tts`.
      3. **Sincronia exata áudio/vídeo**: o `-t` da ENTRADA do vídeo é a duração do trecho original (`clip['duration']`), e o `setpts` (`final_duration / clip['duration']`, ou seja `1/speed_ratio`) é quem ajusta o trecho para durar a duração REAL do MP3 (`final_duration`). NUNCA usar `final_duration` no `-t` de entrada: a escala seria aplicada duas vezes e o `-shortest` cortaria a narração.

      4. **Narração curta = corte curto**: no modo IA a duração do arquivo final é a do MP3. Um roteiro de ~12 palavras gerou um corte de 5 s (o trecho de 30-55 s foi espremido). Por isso: `generate_viral_script_ai` exige no mínimo `MIN_SCRIPT_FILL` (60%) do máximo de palavras e tenta 2 vezes; depois do TTS, `narration_too_short()` recusa narração menor que `max(MIN_NARRATION_SECONDS, duração_do_trecho / MAX_VIDEO_SPEEDUP)`. No modo normal o corte volta ao áudio original; no Passo C o corte é descartado. NUNCA aceitar a duração do TTS sem essa checagem.
      5. **Fade no final**: todos os comandos ffmpeg de saída aplicam `fade_out_filters(duração_do_arquivo_final)` (vídeo `fade` + áudio `afade`, `FADE_OUT_SECONDS`=0,5). A duração passada é a do ARQUIVO FINAL (áudio TTS no modo IA, `clip['duration']` no modo original). Ao criar um novo comando ffmpeg de saída, inclua o fade.

## Sistema de Fallback de Legendas (3 Passos) — NOVO 2025
Para resolver "Legendas: NÃO ENCONTRADAS" em vídeos longos de gameplay:

### Passo A — Legendas do YouTube (Prioridade Máxima)
- **Limpeza de URL:** `clean_youtube_url()` remove parâmetros de tracking, playlist, timestamp, shorts, mantendo apenas `https://www.youtube.com/watch?v=<ID>`.
- **Busca expandida:** `--sub-lang "pt,pt-BR,pt-PT,en"` — inclui inglês como fallback para vídeos internacionais.
- **Formatos:** `.json3` (preferido), `.vtt`, `.srt` — parse unificado via `load_subtitles()`.

### Passo B — Transcrição de Áudio via Groq Whisper API
- **Trigger:** Falha no Passo A OU legendas do YouTube com < 30 palavras (provável gameplay sem narração).
- **Extração de áudio:** `extract_audio_for_transcription()` usa `./bin/ffmpeg.exe`:
  - MP3 mono 64kbps, 16kHz (otimizado para Whisper)
  - **Chunking automático:** Vídeos > 20 min divididos em blocos de 15 min
- **API:** Groq `whisper-large-v3-turbo` via `GROQ_API_KEY` do `.env`
- **Retorno:** Segmentos com timestamps no formato padrão do projeto
- **Validação:** Se total de palavras < 30 → passa para Passo C

### Passo C — Modo Visual Gameplay (Último Recurso)
- **Trigger:** Passo B falhou OU áudio tem < 30 palavras
- **Extração de frames:** `extract_key_frames()` via `./bin/ffmpeg.exe`:
  - 1 frame a cada 30s (ajustado para máx. 20 frames)
  - Resolução 1280x720, qualidade alta
- **Análise visual:** `analyze_frames_with_ai()` manda os frames ao Groq em **lotes de no máximo 3 imagens** (limite do modelo de visão; nunca enviar mais por chamada). Cada frame volta com descrição + nota 0-10; o timestamp vem do NOSSO frame, nunca de número devolvido pelo modelo.
- **Escolha dos clímax:** os frames de maior nota (mínimo `MIN_CLIMAX_SCORE`=5), afastados pelo menos `TARGET_DURATION_MAX` segundos entre si.
- **Geração de roteiro:** `_write_script_for_moment()` escreve a narração SÓ com as descrições reais dos frames (sem inventar fatos).
- **Sem chave ou sem clímax confiável = sem corte.** NUNCA criar roteiro genérico/falso de reserva nem cortar em posições fixas (o antigo `_fallback_visual_analysis` foi removido de propósito). Sem `GROQ_API_KEY` o programa para antes de extrair frames.
- **Modo forçado:** Automático `--audio ia` (narração 100% IA, sem áudio original)
- **Modelos:** nomes ficam no `.env` (`GROQ_VISION_MODEL`, `GROQ_TEXT_MODEL`) porque o Groq descontinua modelos a cada poucos meses; os padrões estão em `DEFAULT_GROQ_VISION_MODEL` / `DEFAULT_GROQ_TEXT_MODEL`. Se a API devolver 400/404 de modelo, confira https://console.groq.com/docs/deprecations.

## Roteiro do modo `--audio ia`
- `generate_viral_script_ai()` reescreve o trecho com um modelo de texto do Groq (a transcrição automática do YouTube não tem pontuação). Se não houver chave, ou a IA falhar/devolver pouco texto, cai para `generate_viral_script()` (regras fixas).

## Geração de Áudio com edge-tts (Regra Obrigatória)
**edge-tts 7.x**: O método `.stream()` de `edge_tts.Communicate` **só pode ser iterado uma única vez** — não se pode chamar `.stream()` e depois `.save()` na mesma instância.

**WordBoundary é obrigatório**: no edge-tts 7.x o padrão é `SentenceBoundary` (um evento por frase). Crie sempre `edge_tts.Communicate(text, voice, ..., boundary="WordBoundary")` para ter um evento por palavra e legendas de 3-5 palavras.

**Idioma das legendas**: ao escolher entre vários arquivos baixados, use `pick_subtitle_file()` (português antes de inglês). Nunca `glob(...)[0]`: a ordem alfabética põe `en` antes de `pt`.

**Padrão correto**: Use um único loop `async for chunk in communicate.stream():` que simultaneamente:
1. Escreve `chunk["data"]` (bytes de áudio) diretamente no arquivo `.mp3` via `open(output_mp3, "wb")`
2. Captura eventos `chunk["type"] in ("WordBoundary", "SentenceBoundary")` para timestamps exatos das legendas `.ass`

Exemplo:
```python
with open(output_path, "wb") as f:
    async for chunk in communicate.stream():
        if chunk["type"] == "audio":
            f.write(chunk["data"])
        elif chunk["type"] in ("WordBoundary", "SentenceBoundary"):
            word_boundary_events.append({...})
```
(O `open()` nativo não suporta `async with`; usa-se `with` sincronizado dentro do loop assíncrono)

## Padrões Obrigatórios de Legenda (.ass)
### Modo Original (legendas YouTube)
- **Zero sobreposição:** Sempre truncar o `end` da legenda atual caso ultrapasse o `start` da próxima.
- **Ritmo de leitura:** Agrupar o texto em blocos curtos de 3 a 5 palavras por vez (estilo dinâmico TikTok/Shorts).
- **Posicionamento:** Usar `Alignment=2` (baixo-centro) e `MarginV=320` para ficar abaixo do quadro central sem encostar nos botões da interface do TikTok/Shorts.
- **Estilos alternados:** Alternar entre estilo `Default` (branco com contorno) e `Highlight` (amarelo) a cada bloco para efeito "karaoke".

### Modo IA (narração edge-tts) — REGRAS FIXAS
- **Fonte única:** Eventos `WordBoundary` do `edge_tts.Communicate.stream()` — timestamps exatos por palavra.
- **UM estilo apenas:** `Alignment=2`, `MarginV=320` — texto NUNCA sobe para o meio da tela.
- **Zero sobreposição:** `end` do bloco atual = `start` do próximo (truncamento estrito).
- **Blocos de 3-5 palavras:** Agrupados respeitando pontuação final (`.!?…`) — fecha chunk ao atingir limite OU encontrar pontuação de fim de frase.
- **Sem alternância de estilos:** Estilo `Default` fixo — sem efeito karaoke, sem `Highlight`.

## Resumo Narrado no Início (modo gameplay; REGRA: o resumo nunca inventa e nunca estraga o corte)
- `add_summary_intro()` (`gerar_cortes.py`) roda DEPOIS do layout, sobre o `.mp4` final de 1080x1920: pega o primeiro quadro, gera 1-2 frases (`generate_summary_intro_text`, 6-20 palavras) com a voz do `edge-tts`, monta uma intro (quadro parado + legenda da fala + voz) e junta intro + corte. Ligado por padrão (`SUMMARY_INTRO_DEFAULT`); desliga com `--sem-resumo`, `CORTES_RESUMO=0` ou a caixa da interface (a interface só manda `--sem-resumo`, e só no modo gameplay).
- **O texto vem só da fala real do trecho** (`clip_text`). `summary_is_grounded()` descarta resumo cujas palavras de conteúdo não aparecem na fala (`SUMMARY_MIN_GROUNDING`). Sem fala, sem chave ou sem resumo bom: o corte sai sem intro.
- **Qualidade primeiro:** a intro é codificada com os MESMOS parâmetros do corte (fps, taxa de áudio, canais, crf) e a junção é `concat -c copy`, sem recodificar o corte. Só se a junção falhar ou a duração do resultado não bater (±0,6 s) é que se usa a recodificação (`juncao: reencode`).
- **Nunca estragar o corte:** o arquivo só é trocado (`os.replace`) quando a versão com intro está completa; qualquer erro devolve `None` e mantém o corte original. Intro + corte ≤ `SUMMARY_MAX_TOTAL_SECONDS` (60 s); sem áudio no corte = sem intro.
- A legenda do corte original já está gravada na imagem, então NÃO precisa ser deslocada: a intro entra antes por concatenação. O `.json` ganha `resumo_intro` (texto, voz, duração, junção) e `duracao_final_s`.
- **Nome do streamer:** vem de `--streamer`/campo da interface ou, senão, do canal (`fetch_video_info` via yt-dlp `-J`; `resolve_streamer_name`). Canal com cara de cortes (`SUMMARY_CUT_CHANNEL_HINTS`) NÃO é usado como nome do streamer. ## Análise Visual de Vídeos (Projeto Todo)
- Sempre que precisar avaliar a qualidade de um corte gerado, analisar um vídeo de referência ou entender o contexto visual antes de editar qualquer script do projeto, utilize a skill `/watch` (`.claude/skills/watch/SKILL.md`). Ela serve para quem DESENVOLVE o projeto (o Claude Code assistindo vídeos); o produto (`gerar_cortes.py`) não a usa.
- **Origem:** a skill é uma cópia do projeto MIT [bradautomates/claude-video](https://github.com/bradautomates/claude-video) (versão e commit em `.claude/skills/watch/UPSTREAM.md`). **Não edite os arquivos dela**; para atualizar, copie de novo a pasta `skills/watch/` do original e atualize o `UPSTREAM.md`.
- **Pré-requisitos (por computador):** Python 3.10+ e, no PATH, `ffmpeg`, `ffprobe` e `yt-dlp`, mais o Deno para links do YouTube. A skill NÃO usa o `./bin/ffmpeg.exe` nem o `python -m yt_dlp` do projeto. Windows: `winget install --id Gyan.FFmpeg --exact`, `winget install --id yt-dlp.yt-dlp --exact`, `winget install --id DenoLand.Deno --exact` (reabra o terminal depois).
- **Configuração padrão do time (na pergunta da primeira execução, que fica em `~/.config/watch/.env` de cada pessoa):** motor `local` (nada sai da máquina, sem custo de API) e detalhe `efficient` (até 50 quadros; cada imagem consome tokens do plano do Claude). Para transcrever vídeo sem legenda use `groq` (a chave do projeto) ou `none`. NÃO instale o `whisperx` (baixa ~1,5 GB e roda um instalador externo) e só use o motor `gemini` com decisão explícita do líder: ele envia o vídeo ao Google.
- Para um corte já gerado (arquivo local), prefira `--engine local --detail efficient` e passe a pergunta com `--question`. Para vídeos longos, restrinja com `--start`/`--end`.
- Nunca escolha minutagens aleatórias: ao sugerir ou programar cortes, garanta começo (gancho), desenvolvimento e conclusão de raciocínio baseados no contexto completo do vídeo.
